# HANDOFF — 2026-07-07 (parte c) — borrado quirúrgico de imágenes (shop admin)

## Contexto
El bug "subo/edito algo y se borran fotos de **otras** publicaciones" seguía
apareciendo después del fix de ayer (`d3bbd1c`). Ese fix tapó **una** fuente
(índice stale **dentro** del mismo producto). Faltaba la fuente **cross-producto**.

## Causa raíz (cross-producto)
- Guardar producto es **destructivo por diseño** (`shop.js` PUT = `DELETE FROM
  product_images` + reinsert de toda la galería que manda el cliente). No hay
  diff: si el cliente manda una lista incompleta/vieja, el server borra el resto.
- El único punto que escribía sobre **otra** publicación era la **×** de "Fotos
  por medida" sobre una variante hermana: `deleteHeroCandidate` rearmaba un PUT
  completo con `owner.images` de `allProducts` — un **snapshot** cargado una sola
  vez al abrir el panel. Si esa variante había recibido fotos nuevas después (ej:
  las re-subidas a mano tras el bug de ayer), el PUT las **pisaba con la versión
  vieja → se borraban**.

## Hecho (pusheado, auto-deploya Render + Vercel)
- **`63dbd09`** — `fix(shop)`: nuevo endpoint quirúrgico
  **`DELETE /api/admin/shop/products/:id/images?url=…`** que borra **sólo** la
  fila que matchea la url (transacción), sin tocar el resto. Si la borrada era la
  destacada y quedan otras, promueve la de menor `sort_order`. Devuelve galería
  fresca. El cliente (`deleteHeroCandidate`, la ×) ahora llama a ese endpoint y
  sincroniza `owner.images` con lo que devuelve el server, en vez de restar sobre
  el snapshot viejo. **Mata la clase entera de pérdida cross-producto.**
- **`aead9e2`** — `refactor(admin)`: eliminado `uploadImageFile` muerto (la vieja
  subida por índice stale, ya sin call-site; la reemplazó `addImageWithFile` con
  tokens). Sacado también el state `uploadingIdx` de `ProductModal`. Se dejó para
  que nadie lo recablee y reintroduzca el bug.

## ⚠ Importante (sigue igual que en parte b)
- Esto evita pérdidas **de acá en adelante**; **NO restaura** lo ya borrado antes
  del deploy. Para recuperar → **restore de Neon** (point-in-time), el usuario
  tiene acceso.
- **Local ≠ prod:** el `.env` local apunta a otra base y el JWT no vale en Render.
  No puedo leer/escribir data real de prod; los cambios de **código** sí llegan por
  deploy.
