## 2. Hardening de seguridad (commit `e88f8bb`)

Auditoría con 5 revisores en paralelo (auth/JWT, economía de monedas, checkout/pagos,
infra/secretos, cliente React). Fixes por severidad:

**CRÍTICO**
- Escalada operator→admin (`POST /operator/clients` aceptaba `role` del body) → sólo admin crea staff.
- Race de saldo (TOCTOU) en **toda** la economía (canjes, gift, misiones, ruleta, items, powers, salas) → débito atómico `WHERE balance>=costo RETURNING` (advisory lock en ruleta). Impedía doble gasto / balance negativo.
- Stored XSS vía `evidence_url` de IG (se abría en el panel admin → robo de token) → validación http(s) server + render seguro.
- Token de reset de password con `Math.random()` → `crypto.randomBytes(32)`.

**ALTO**
- Checkout confiaba en header `Origin` para URLs de pago (phishing + fuga del secret del webhook MP) → sólo `APP_URL` del env.
- Race del código promo (bypass de `max_uses` en códigos 100% off) → incremento atómico con re-chequeo dentro de la transacción.
- `npm audit fix` → **0 vulnerabilidades** (había CVE crítico en sanitize-html).
- Rate limit en `/auth/reset-password`; `dangerouslySetInnerHTML(post.body)` → texto plano.

**MEDIO/BAJO**
- JWT_SECRET fail-closed (salvo `ALLOW_INSECURE_JWT_SECRET=1`); stock que se descuenta de verdad (antes oversell); privacidad del perfil aplicada server-side; bloqueo respetado en mensajes privados; anti formula-injection en export CSV; race del invite-code; webhook MP idempotente; JWT fijado a HS256; limpieza de archivos basura del repo; bcrypt 10→12 en staff.

**Ya estaba bien** (no se tocó): precios/totales siempre server-side, webhook MP re-verifica el pago contra su API, WebAuthn impecable, API keys cifradas AES-256-GCM, SQL parametrizado, helmet+CSP, CORS con allow-list.
