## 2. Cómo funciona el buscador de la lupa

Todo vive en `landing/src/components/Header.astro` (markup + script
inline) y `landing/src/styles/global.css` (bloque `.header__search*`).

- **Índice en build**: secciones del nav (menos Inicio) + los 29 productos
  de `productos.js` con nombre, precio e imagen.
- **Matching**: normaliza acentos/mayúsculas (`NFD` + strip combining) y
  exige que TODOS los tokens del query estén en el label. Máx 8 resultados.
- **Destinos**: productos → `/shop?q=<nombre>` (Shop.jsx ya filtraba por
  `?q=`, no hubo que tocar el portal); secciones → su interna. Enter →
  `/shop?q=<query>`. Sin resultados → link "Ver toda la tienda".
- **UX**: overlay fijo bajo el header (top 60px, mismo patrón que el menú
  mobile), backdrop oscuro que cierra al click, X y Escape también
  cierran. Input a 16px para que iOS no haga zoom al enfocar; focus dentro
  de `requestAnimationFrame` para que iOS lo acepte.
- **Convivencia con la hamburguesa**: abrir el buscador cierra el menú
  mobile y viceversa (listeners cruzados, los scripts son IIFEs separadas).
- Resultados con thumbnail 40px (o placeholder "→" para secciones),
  precio en verde `#1FA350` formateado `es-AR`.

## 3. Aprendizajes / trampas

- La lupa era **UI huérfana de nacimiento**: botón con `aria-label` pero
  cero JS desde que se creó el Header. Si un ícono de acción se shipea
  sin handler, o se cablea o se saca — el cliente lo reporta como "roto".
- El regex de strip de acentos conviene escribirlo con escapes
  (`/[\u0300-\u036f]/g`) y no con los combining chars literales: el Edit
  tool no distinguía el old/new string (los combinantes se renderizan
  igual) y hubo que aplicarlo vía script Python.
- El HTML de resultados se arma con `innerHTML` pero TODO valor
  interpolado pasa por `esc()` (labels, hrefs, query del usuario) — los
  nombres de producto los edita el cliente a futuro, no son confiables.
