## 3. 🐛 "Compro monedas y no se suman" — root cause + fixes (`44fe495`)

El cliente probó con un **código de descuento 100% off** y las monedas no se
acreditaban. Diagnóstico contra prod (sin acceso a DB, via API pública):

- El server de prod SÍ corría el código de monedas (packs renombrados OK).
- `shop.shipping_cost_cents` está en **$0** en prod (verificado creando
  órdenes de prueba).
- Se encontraron y arreglaron 3 grietas reales:

### Fix 1 — `authOptional` (server/auth.js + checkout.js)
El checkout sólo exigía sesión para `payment_method=monedas`; para MP,
transferencia y órdenes gratis **ignoraba el Bearer** → `orders.user_id`
quedaba NULL y la acreditación dependía de que el email tipeado coincidiera
con el de la cuenta (`resolveOrderUserId` por email). Ahora `authOptional`
popula `req.user` si viene token válido (guest sigue funcionando igual).

### Fix 2 — el client manda el token siempre (ShopCheckout.jsx)
Antes sólo lo mandaba con `payMethod === "monedas"`. Ahora siempre que haya
sesión → la orden nace linkeada a la cuenta, pague como pague.

### Fix 3 — envío post-descuento con dos exenciones (checkout.js)
El envío se sumaba ANTES de evaluar el descuento → con envío configurado un
código 100% dejaba `total = envío > 0` → la orden se iba a MP y nunca se
auto-aprobaba. Ahora el envío se calcula después del descuento y es $0 si:
- el carrito es 100% digital (sólo packs de monedas — no se despacha nada), o
- el código cubre todo el subtotal (`discount >= subtotal` — comp/giveaway).

Resultado: **código 100% → total $0 → la orden nace `paid` → `onOrderPaid`
acredita monedas/puntos al instante** (ese circuito ya existía, F5+; sólo no
llegaba a dispararse). Verificado por el cliente en prod. ✅
