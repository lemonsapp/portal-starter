## 1. Eyebrow "TRES RAZONES" — centrado real  (`23d35db`)

### Causa (CSS puro, por eso sobrevivió a todos los fixes de JS/SplitText previos)
- La píldora es `inline-flex` y se ajusta al ancho del texto. Pero
  `letter-spacing` agrega un hueco **después de la última letra también**. Ese
  espacio fantasma inflaba el lado derecho → padding derecho > izquierdo → el
  texto se veía corrido a la izquierda y desprolijo.

### Hecho
- `.ease-of-use__eyebrow-text { margin-right: -<letter-spacing> }` en ambos
  breakpoints (640px: `-0.11em`, 400px: `-0.09em`). Cancela el trailing space;
  el pill abraza sólo los glifos visibles → padding simétrico, texto centrado.
- Archivo: `landing/src/styles/global.css` (bloques `@media (max-width:640px)`
  ~línea 4055 y `@media (max-width:400px)` ~línea 4116).

## 3. Admin shop — fotos por medida no se pisan + modal no cierra  (`2db7166`)

Archivo único: `client/src/pages/AdminPanel.jsx`.

### Bug #2 (GRAVE — pérdida de datos). Causa raíz
- El producto abierto (ej. "RACE 1 NPK") **aparece a sí mismo** en su lista
  "Imágenes por medida" (marcado "· esta"; `medidaSiblings` lo incluye porque
  filtra por `famKeyOf` sin excluir el propio id — ver `isThis` en ~línea 2095).
- Flujo roto: subís fotos a la medida 250 → "Guardar imágenes de esta medida"
  (`MedidaImageEditor.save()`) las PUTea OK al server, pero **no avisaba** al
  form principal del modal, cuyo estado `images` (init en ~línea 1599 al abrir)
  seguía viejo/vacío. Luego "Guardar cambios" (`ProductModal.save()`, ~1810)
  re-PUTea el **mismo id** con esa lista vieja → **pisa las fotos recién subidas**.

### Fix #2
- `MedidaImageEditor` ahora recibe `onSaved(images)` y lo llama tras guardar OK.
- En el render (~2109), si `sib.id === product?.id` → `setImages(...)` sincroniza
  el estado del form principal. Así "Guardar cambios" ya no pisa. Para kits
  (siblings con id distinto) no cambia nada: siempre se guardaron independientes.

### Bug #1 (UX) + Fix
- Antes `onSaved={() => { setEditing(null); load(); }}` cerraba el modal y volvía
  a la lista. Ahora `onSaved={() => { load(); }}`: refresca la lista de fondo,
  **deja el modal abierto** en el mismo producto, y `save()` setea
  `savedMsg` → se ve "✓ Cambios guardados" arriba. Botón "Cancelar" → "Cerrar".
